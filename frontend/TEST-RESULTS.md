## Phase B — browser validation

The final Phase B build passed strict TypeScript checking and Vite production compilation. `pnpm test` passed **18 tests**, including continuous audio DSP, three-language key parity, a scan of literal UI keys and backend error codes, locally generated QR decoding, CSRF/PATCH conflict metadata and multipart upload handling. The original AudioWorklet remains unchanged. QR generation runs locally with `qrcode`; test decoding uses `jsQR`.

`node tests/e2e/actual-phase-b.mjs <isolated phase-b-fixture.json>` passed **12 groups** through the actual production frontend, PHP HTTP service, Workerman and isolated PostgreSQL database. No browser HTTP/WebSocket interceptions were installed. These tests use explicitly synthetic stored source/translation text and sample timing; they make **no real Qwen/OSS or microphone calls**. Checks cover 90-day session issuance/device management, forced password changes, local QR and saved named PNG decoding, clipboard denial fallback/focus restoration, concurrent correction conflicts/live updates, four actual export files and original/current versions, append-only restoration history, persistent classroom search/sort and rename, three-language mobile large captions, real Excel template/upload/preview/queued confirmation, admin access control, exact private sharing/revocation and logout of all devices. Zero JavaScript errors and microphone requests were recorded. Screenshots were visually reviewed.

The first timed-export attempt failed because its explicit synthetic fixture used the unsupported `synthetic_segment` timing label. The formatter correctly rejected that snapshot with `export_empty_timed`. The fixture alone was corrected to valid `server_segment` sample ranges and new TXT/Markdown/SRT/WebVTT jobs passed. The failed snapshot was not changed. Resulting export files remain **synthetic-content/synthetic-timing artifacts**, not evidence of model timing accuracy. Other early test attempts exposed strict selector mismatches; their scripts were corrected and failure reports preserved.

`node tests/e2e/actual-phase-b-audio.mjs <isolated phase-b-audio-fixture.json>` passed **6 additional groups** through actual PHP/Workerman/PostgreSQL and the production AudioWorklet, using a synthetic 440 Hz MediaStream and the explicit upstream Qwen mock. Three clients included two devices of the same account and one guest. Tests checked explicit microphone preparation, uninterrupted capture while changing language/QR/font/large-view/fullscreen fallback, rejection without stopping the valid recorder, live recording-right transfer, paused transfer without automatic capture and final flush/persistence. **43 packets** were durably acknowledged and matched the database sample count. All tracks stopped; guest microphone requests and JavaScript errors were zero. This suite deliberately excludes OSS archive workers and physical audio devices. Fullscreen unavailability was injected solely to test fallback.

The actual transfer test exposed an outbox ordering race: a delayed lesson snapshot could overwrite a newer `recorder.ready` snapshot, including within the same epoch. The frontend now tracks a separate `lastLessonSeq`, applies the ready message's current lesson and ignores stale lesson events while preserving delivery of independently sequenced subtitle events. A new isolated ready classroom and restarted gateway passed the entire six-group run.

`node tests/e2e/actual-phase-b-active-lesson.mjs <isolated phase-b-fixture.json>` separately passed the actual **409 existing-classroom** flow: the creation modal retains the returned lesson ID and explicitly opens that exact unfinished classroom, with zero microphone calls and JavaScript errors.
