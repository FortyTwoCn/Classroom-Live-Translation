# Browser app — Phases A and B

This is a live Vue 3 client for the PHP API and WebSocket gateway. It has no runtime fake subtitles or silent model fallback. Physical-device and external-service verification boundaries are recorded in `TEST-RESULTS.md`.

## Build and development

Use Node.js 22+ and pnpm. Run `pnpm install --frozen-lockfile`, `pnpm test`, and `pnpm build`. The build publishes `../public/app.html` and `../public/assets/` while preserving Laravel's `public/index.php`; serve them through the project's Nginx HTTPS origin. The Laravel fallback route serves `app.html`. `pnpm dev` proxies `/api` to `http://127.0.0.1:8080` and `/ws` to `ws://127.0.0.1:8081`. Override `API_PROXY_URL` / `WS_PROXY_URL` for local services. The API `/api/me` provides the browser WebSocket URL; configure its origin and port for the URL visitors actually use. HTTPS pages require WSS. No provider secret is read by this app or exposed via `VITE_*`.

## Capture and verification boundary

An authorized recorder must click **Local microphone test** or **Start recording**. Viewers never request microphone access. Preparation meters the local audio but never uploads it. Server `recorder.ready` authorizes transmitting PCM. AudioWorklet uses the actual input rate, a persistent 63-tap FIR low-pass filter and continuous rational resampling into mono 16 kHz PCM16 little endian. Normally each packet contains 1600 samples / 100 ms; an orderly stop can flush a shorter final packet. Binary header: `uint32be recorder_epoch`, `uint32be sequence`, then PCM. The server must acknowledge only durably accepted audio. At most 10 packets remain unacknowledged, and WebSocket buffered bytes are capped at 64 KB; exceeding either safely stops tracks and sends pause. The client does not replay uncertain audio to the model.

Pause, end, navigation, logout, loss of recording permission, track termination, AudioContext suspension, and page backgrounding stop microphone tracks. Reconnecting viewers get a fresh authorization ticket and a server snapshot; reconnection never reopens a microphone. The screen wake lock is best effort. Physical devices and background restrictions still require explicit real-device tests. Sources: [MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia), [MDN AudioWorklet](https://developer.mozilla.org/en-US/docs/Web/API/AudioWorklet), [MDN Screen Wake Lock](https://developer.mozilla.org/en-US/docs/Web/API/Screen_Wake_Lock_API).

Source and translation model units remain independent; the client does not invent ID associations or sentence alignment. Only real server `completed` units show as confirmed. Media positions missing from the server remain unavailable; server segment positions show as approximate. A native audio player appears only after archive status `playable` and an authorized playback response.

## Tests

`pnpm test`: synthetic signal conversion, block continuity, anti-alias rejection, PCM clipping and byte order, binary headers, bounded backpressure, and complete Phase A locale key parity. These are algorithm and simulated tests, not real model, OSS or physical microphone tests.

`pnpm exec playwright install chromium webkit` then `pnpm test:e2e`: mocked HTTP and a loopback WebSocket test fixture in Chromium and WebKit for guest microphone isolation, language switching, a mobile-size Ukrainian layout, and an oscillator-generated MediaStream exercising the real AudioWorklet/PCM upload and track-stop code. Those are simulated browser tests; they do not verify actual iPhone, iPad, Android, Chrome/Edge/Safari microphones, model calls or OSS. Windows WebKit builds omitting AudioContext/MediaStream explicitly skip the audio test. On this machine, downloaded Chromium cannot launch due to its Windows side-by-side configuration; set `$env:PLAYWRIGHT_CHROMIUM_CHANNEL='msedge'` in PowerShell to run the Chromium engine through the installed Edge. See `TEST-RESULTS.md`. Orderly pause/end waits up to 1.5 seconds for durable acknowledgements of the final partial packet; timeout is shown explicitly and requests pause instead of reporting saved/end success.

For a real HTTP empty-database deployment check, `pnpm test:actual-http` uses the actual localhost:8080 PHP app without API/WS mocks and captures three languages at three viewport sizes. For browser capture against the isolated actual PHP/Workerman/PostgreSQL services with a synthetic microphone and mocked Qwen, run `node tests/e2e/actual-browser-capture.mjs <gateway-fixture.json>` after preparing a fresh ready test lesson. These classifications and results are separated in `TEST-RESULTS.md`; neither suite verifies a real model, OSS or physical microphone.

For the actual model/storage loop, first run the real PHP gateway, Qwen, archive and OSS upload workers using an isolated database, private OSS test prefix and a fresh ready lesson. Run `pnpm test:real-services <real-gateway-fixture.json> <synthetic-english-speech.wav>`. The supplied speech replaces hardware microphone input explicitly; it passes through the production AudioWorklet, actual PHP WebSocket gateway and Qwen. Three clients are checked against persisted text, followed by private OSS archiving, native audio playback and signed Range retrieval. The test stores no signed URLs or secrets. The recorded run passed; see `TEST-RESULTS.md` for exact counts and the remaining physical-device/deployment boundary.

## Phase B product functions

The UI includes lesson search, filters, stable sort direction and pagination; renaming; optimistic subtitle corrections, retained conflict drafts, original model text, revision history and restoration; recording invitations/requests/device preparation/takeover; 90-day remembered login, device revocation, password change and all-device logout; and a responsive administration area for users, courses, lessons, sentences and asynchronous Excel import. Sensitive actions use the server's recent-password authorization, with a local confirmation dialog. Server API permissions remain authoritative.

Each accessible lesson has an independent QR button beside the language selector. QR generation and named PNG composition run locally with the bundled `qrcode` library; access tokens are never sent to a third-party QR service. Failed clipboard copying selects a manual-copy field. Native modal dialogs trap keyboard focus, return focus to the trigger, and include their own language selector. Forced-password dialogs cannot close without changing the password or logging out.

Large subtitles use the existing lesson connection and microphone instance. Font sizes 24/32/40/48/64, source/translation/bilingual selection and follow preference are stored locally. Explicit fullscreen falls back to the in-page layout when unavailable. QR/locale/size/layout changes do not start a model session or microphone. Active recorders retain pause/end controls and handoff dialogs. Returning to normal mode preserves reading position and correction drafts. Subtitle DOM is capped at 500 units; older content and multilingual keyword results come from authorized paginated APIs.

TXT, Markdown, SRT and WebVTT exports are real server snapshot jobs. Users choose source/translation/bilingual and original/current text, see progress, explicit omissions and timing warnings, retry failures and receive a controlled download. The browser never generates substitute transcripts or invented timestamps. Admin course soft-deletion confirmations show dependency counts; archive, share-policy and sentence deletion/restoration actions use server endpoints.

`pnpm test:phase-b <phase-b-fixture.json>` checks these flows against isolated actual PHP/WS/PostgreSQL and explicit synthetic stored subtitles, without any model/OSS calls or browser HTTP/WS mocks. `pnpm test:phase-b-audio <phase-b-fixture.json>` requires a fresh ready lesson and a separately configured mocked upstream provider; synthetic tone input exercises actual AudioWorklet capture, same-account device handoffs and mode changes. Keep real external-service results distinct from these suites.

## Phase C reliability and administration

The administrator settings page reads only masked secret indicators, keeps existing secrets when input fields are blank, uses optimistic version checks and preserves drafts on conflict. Model and OSS connection tests require explicit consent and a separate confirmation, run asynchronously, and display only safe diagnostic steps. A model connection test sends no speech and does not by itself establish transcription quality. Retention, daily/classroom quotas, session rotation, upload limits and manually maintained decimal-string prices use real server policy APIs. Prices retain region, currency, effective date and optional source/verification metadata; unknown provider usage or missing prices remain unknown, and currencies are never silently summed.

Course terminology changes apply when a new lesson first starts. UTF-8 source and target limits are shown separately (256/64 bytes locally), optimistic glossary versions preserve conflicting drafts, and sensitive changes use recent-password authorization. Usage and operational diagnostics are restricted to the proper server roles. Course selectors retrieve all server pages rather than only the first 30 options.

Viewer reconnection applies ordered missed events before merging the latest snapshot, retaining previously loaded history and correction drafts. Capture failure stops tracks, requests pause and reports the reason, acknowledged sequence and explicitly unknown missing range to the server. There is no automatic uncertain-audio replay or microphone reopening. Model rotation uses its own event without rebuilding the microphone; failure to prepare a replacement session leaves the existing session running while the server retries.

Historical playback has native play/pause/seek, speed, elapsed/total time and trusted segment highlighting with optional follow. Missing old segments load through authorized `around_id`/`at_sample` APIs. Course-wide UTF-8 search opens the exact unit without autoplay. Original-audio download requires both global and course permission; server authorization still governs the controlled attachment endpoint. Controlled permanent cleanup requires an ended, soft-deleted classroom and its exact name, waits for worker completion, and explains that audit records, backups and external caches have separate retention boundaries.

`pnpm test:phase-c <phase-c-fixture.json>` uses actual isolated PHP/PostgreSQL and native WebSocket connections. Its historical index is explicitly synthetic. A fixture may borrow an existing real OSS synthetic-speech archive for **read-only** playback/range checks: it must identify a separate empty classroom for destructive cleanup, and the script rejects a purge target equal to the playable classroom. Never use a production fixture. `pnpm test:phase-c-capture <phase-c-fixture.json>` requires a separately configured mock Qwen endpoint; it creates an explicitly synthetic classroom and uses real AudioWorklet tone input to verify track-ended/context-suspended capture issues without any real provider/OSS call. Reports separate these classifications.
